# 采购逐项确认、账号工作组与操作记录验证

日期：2026-11-01。此次交付为工作区源码和前端构建，未提交、发布或打包 Windows 正式版。

## 交付内容

- 采购清单每一项可独立确认，未确认项可继续编辑；未被业务引用的已确认项可填写原因撤回。采购单及库存历史引用会锁定对应项，不影响其他项。兼容旧整单确认接口，旧报价保存行快照，避免后续编辑改变历史报价。
- 主账号管理账号备注名、密码、启停、工作组命名和转组；一个普通账号只属于一个工作组。按项目、模块查看权限、操作权限及敏感字段授权。接口、附件、导出、汇总、历史和幂等重试统一执行后端授权。
- 原业务页面可打开操作记录，显示操作时的人员备注名、工作组、时间、变更和原因。上传文件显示上传者；采购单汇总到货、付款和进项发票等子操作。原有历史资料没有已知操作者时明确显示未记录。
- 账号切换、转组或撤权后清理旧身份缓存、草稿和未知结果待重试请求，防止使用前一个身份重放操作。

## 数据兼容与保护

- 增量迁移为 `026_accounts_access.sql`、`027_procurement_line_confirmation.sql`、`028_operation_history.sql`。合成旧库从 025 升级后，原采购单、税额、库存流水、报价等原列值和行数保持一致；新增逐项状态与报价快照按历史事实回填，重复迁移无额外变化。
- 未启动或迁移原业务 DATA，也未改原 `config.json`。验证数据库、配置和附件全部位于 `tmp/accounts-procurement-20261031/` 的独立合成数据目录。
- 开始和结束时工作区根目录均无 DATA/Data/data/config.json。没有访问其他客户数据目录。
- `updater/engine.go`、`updater/dns.go`、`updater/dns_test.go` 与开发开始前的 SHA-256 一致，原 DNS 修复保留。
- 首次使用新源码打开旧库，须在运行服务的本机输入原共享口令并创建主账号；旧 Cookie 不会自动获得主账号身份。随后由主账号授权工作组。
