# v1.2.15 发布前定向排查

在局域网 HTTP UUID 修复基础上，继续检查安全上下文 API、未知请求恢复、账号切换和权限刷新。使用系统化调试：先复现，再修复，再检查原样重试和拒绝路径。没有运行业务全量回归。

## 确认并修复的问题

| 问题 | 原因与处理 |
| --- | --- |
| 局域网新建／确认采购清单报 `randomUUID` 不存在 | 共用 UUID v4 生成函数，HTTP 使用安全随机字节；14 处调用统一替换，保留幂等键生命周期。 |
| 公司保存成功后误弹未保存提示 | 成功响应后先标记已提交再跳转；未保存和失败请求继续受保护。 |
| HTTP 文档复制失败，错误后正文消失 | 标准剪贴板 API 受安全上下文限制，缺失时在用户点击内使用复制命令；不绕过标准 API 的权限拒绝。失败保留正文并提供可选择的文本／链接，清除旧成功提示。 |
| 新建项目明确放弃后无法提交新内容 | UI 原来仅删除待提交提示，底层 sender 仍锁定旧 payload。现在按原 payload 显式清理 sender，成功后才关闭 UI；项目关闭／恢复同步处理。 |
| 账号、工作组、重置密码断网后可改内容，却永远无法提交 | 复用统一编辑器：未知结果冻结原内容，允许同键重试；明确放弃后才允许新提交。关闭或同账号权限刷新不丢请求。密码仅留在当前内存，不写本地存储或日志。 |
| 权限版本刷新导致发票等请求换编号，可能重复创建 | 发送器与未确认请求按稳定账号＋项目保留；最新权限回调独立更新。后台已保存但响应丢失后，刷新权限仍以原编号确认结果。 |
| 恢复待提交内容未再次检查权限 | 保存操作所需读写权限，恢复按钮和执行入口都重新检查；发票冲销、垫资修改／报销／冲销按具体操作检查。账号切换清缓存。 |
| 旧权限模型被恢复，或数据未读完就重试导致请求丢失 | 不恢复旧快照；从服务端重新读取。读取中或失败时禁止重试并保留原请求，允许刷新，恢复后继续使用原编号。 |

- 原始分组账号真实采购流程与反向权限检查见 `2026-11-11-lan-http-uuid.md`；截图和接口结果归档到发布批次 `verification/prior-fix/`。
- 新增持久回归覆盖 HTTP UUID、复制与失败恢复、项目放弃后重新提交、工作组跨权限版本重试、发票响应丢失与慢读取、撤权禁止重试。
- 独立审查使用实际组件及默认 HTTP repository，模拟服务已提交后响应丢失；确认同键恢复不会生成第二条发票。延迟读取、读取失败再恢复、撤权均有专门验证脚本。
- 真实浏览器使用局域网 HTTP，普通分组账号成功复制文档全文和指定版本链接，实际剪贴板内容一致；主账号创建工作组并显示保存成功，控制台无错误。
- 发布批次：`dist/releases/20261111-v1215-01/`；最终测试、Windows 原生运行与 v1.2.14 升级、GitHub／蓝奏分发及自动清理结果以该批次 `verification/REPORT.md` 为准。
