# 上线问题排查与修复验证

日期：2026-11-11。基线：v1.2.13（`cd93e28`）。本次交付为工作区源码与前端生产构建；未提交、发布或重新打包 Windows。

## 已复现并修复

| 问题 | 实际影响 | 修复 |
| --- | --- | --- |
| JSON 授权依赖 Content-Type | 改为 text/plain、非标准 JSON 类型或伪造 multipart 后，部分接口可写入未授权项目、越权取消报价 | 授权按实际端点解析方式读取内容；真实文件上传继续使用有大小限制的解析器 |
| Excel 导入遗漏价格权限 | 无采购价格权限的账号可以导入带成本价、报价的工作簿 | 预览、确认事务及幂等缓存重放均重新校验实际行字段；预览后撤权也不能继续写入 |
| 删除后 SQLite 复用采购行 ID | 旧页面持有相同 ID 和 revision，可能覆盖或删除新物料；操作历史混入后来的记录 | 新增 029 增量迁移和持久 ID 上限；覆盖采购项新增、复制、导入与采购单行创建、重建 |
| 报价文本被解释为 Excel 公式 | 以等号开头的标题、备注或物料字段导出后会成为公式 | 所有用户文本明确写为字符串，数字和金额输出保持原有规则 |
| 普通 403 引发会话刷新循环 | 访问未授权项目书签后，页面可能反复卸载与请求 | 已登录错误响应携带权限版本；同版本拒绝原地显示，真正版本变化才刷新；无版本头时做有限兼容刷新 |
| 旧账号错误响应晚到 | 切换账号后，旧请求的 401/403 正文可能干扰新会话 | 读取错误正文后与异常处理时再次检查账号代次，旧响应不再触发新账号退出或刷新 |
| 受限库存余额为空时前端崩溃 | 只有项目库存权限、无共享库存权限的普通账号无法打开库存页 | 类型声明兼容空值，界面明确显示无权限；禁用余额筛选，项目领用由后端校验实际库存 |
| 账号页直接打开或刷新 404 | 发布静态包缺少 `/accounts` 的前端路由回退 | 将该明确路由加入允许列表，仍保留未知 API、资源的 404 |
| 成功备份恢复后状态互相矛盾 | 概览成功，但手动任务显示中断，操作记录只有开始备份 | 快照只归一化当前备份任务并补齐当前完成事件，保留原操作人、工作组及其他历史 |
| 正常退出截断手动备份 | daemon 线程随进程结束，留下未完成目录 | 手动任务由应用生命周期管理；正常退出等待已有任务完成并记录成功或失败，退出等待不占用事件循环 |

## 数据兼容与保护

- 029 只新增辅助表，不重建或改写既有业务行、外键、金额和历史事件。ID 上限同时考虑现存行、报价快照、操作记录及幂等缓存中的历史引用。
- 合成旧库验证覆盖迁移后原值保留、已删除 ID 不再分配、事务回滚、重复迁移与重启后持久化。
- 此修复防止后续 ID 复用，不猜测或重写修复前已混合的历史事件。
- 没有启动或迁移客户数据库。所有合成数据、备份和配置均位于 `tmp/production-debug-20261111/`。
- 工作区根目录的 `DATA`、`Data`、`data`、`config.json` 在开始和结束时均不存在，没有创建这些原业务路径。
- `updater/engine.go`、`updater/dns.go`、`updater/dns_test.go` 的 SHA-256 与基线一致，原 DNS 修复未改动。
