# Go 后端与 Windows 程序

本模块包含全部生产后端、原生启动器、更新器和打包器，不依赖 Python 或 CGO。

| 目录 | 职责 |
|---|---|
| `cmd/service` | HTTP 服务入口、数据库初始化、维护模式与优雅退出 |
| `cmd/launcher` | 单实例启动、托盘、打开浏览器、服务进程管理 |
| `cmd/upgrade` | 旧安装迁移、独立安装与失败恢复 |
| `cmd/package` | 生成完整包、组件包、更新清单和校验文件 |
| `internal/api` | 兼容现有业务接口与测试 |
| `internal/config` | 保留并校验既有配置 |
| `internal/database` | SQLite、迁移与数据身份规范化 |
| `internal/lifecycle` | 跨平台进程锁 |
| `internal/update` | 下载、校验、备份、替换、恢复、清理 |
| `internal/distribution` | 确定性打包与资产核验 |
| `migrations` | 内嵌原 001—023 SQL 迁移，不改编号 |

从项目根目录 README 获取完整开发、Windows 构建和升级命令。生产发布必须通过 `.github/workflows/release.yml` 中的成品启动和升级测试；交叉编译不能代替目标系统运行验证。

## 兼容性约定

金额继续用整数分，数量按原接口的十进制字符串处理。数据库迁移保持原有记录，升级不重写历史账务。旧密码、会话签名、幂等请求哈希与 JSON 字段通过参考夹具和 HTTP 回归验证。

`testdata/legacy-routes.json` 固定原业务路由；仅更新协议从旧两步下载/安装改为一键持久任务。`internal/api/testdata/` 仅包含合成业务数据与旧实现的预期结果，不能放入客户数据。

写入使用独立连接的 `BEGIN IMMEDIATE`，文件发布与数据库提交绑定；需要多次查询的读取使用同一只读快照。升级先停止写入和服务，再备份原配置、数据库和附件，验证新程序健康后解除维护状态。

程序清理由安装清单、旧版官方文件哈希和归属记录限定。未知文件不按目录批量删除。升级只保留最近一次受管恢复备份；占用导致的清理失败留有重试记录。
